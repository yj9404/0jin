## 만든 이유

가족 모임에서 다 같이 풀 퀴즈를 TV와 각자의 휴대폰으로 진행하려고 만들었다. 처음에는 노트북 한 대에서 서버를 켜는 방식이었고, 지금은 Cloudflare 위에서 한 퀴즈에 400명까지 참가할 수 있게 바꿨다.

## 구조

- 퀴즈(방) 하나가 Durable Object 하나다. 참가자·TV·진행자 화면이 WebSocket으로 같은 방에 붙는다.
- Worker가 내 퀴즈 API(만들기·목록·복사·삭제), WebSocket 연결, 사진 업로드·조회를 맡는다. 진행자 계정과 퀴즈 목록은 D1, 사진은 R2에 저장한다.
- 진행자는 구글 로그인(OAuth + PKCE)으로 퀴즈를 만들고, 참가자는 로그인 없이 QR로 들어온다.
- 화면은 TV, 진행자, 개인(참가자) 세 가지다. 퀴즈는 만든 날부터 90일 보관한다.
- 맞히면 최고 점수의 절반에 남은 시간 비율만큼 나머지 절반을 더한다. 참가 인원과 무관한 규칙이다.

## 기술 스택

- Cloudflare Workers, Durable Objects(WebSocket Hibernation), D1, R2
- React 19, TypeScript, Vite
- 테스트: 휴대폰 4대·진행자 2명·TV를 흉내 내는 시뮬레이션, 400명 부하 테스트

## 어려웠던 점

**맞힌 순서의 정확성.** 방 하나가 Durable Object 하나라서 모든 제출이 한 곳에서 도착 순서대로 처리된다. 점수에 쓰는 시간도 서버가 답을 받은 시각이다.

**400명 동시 접속.** 화면 갱신은 0.3초 단위로 묶어서 보내고, 화면 데이터는 방송 한 번에 한 번만 계산한다. 참가자와 TV에는 명단 대신 인원·요약과 상위 10명만 보낸다. 로컬 부하 테스트에서 400명이 같은 순간 답을 내면 마지막 응답까지 0.3~0.4초였다.

**저장 최소화.** 바뀐 것만 저장한다(제출 하나가 키 하나). 점수는 저장하지 않고, 불러올 때 마감된 문제의 제출 기록으로 다시 계산한다.

**대기 중 비용.** Hibernation API를 써서 아무도 메시지를 보내지 않는 동안에는 과금되지 않는다. 연결 확인용 ping/pong은 Durable Object를 깨우지 않는다.

**재접속.** 휴대폰에 저장된 참가 토큰으로 이름과 점수를 잇는다. 토큰이 없으면 같은 이름으로 기존 자리를 이어받고, 그 이름이 접속 중이면 거부한다.
