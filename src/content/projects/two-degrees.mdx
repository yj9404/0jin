## 만든 이유

소개팅을 시켜 달라는 지인들의 부탁이 계속 있었다. 처음엔 머릿속과 메모로 관리했는데, 누구와 누가 맞을지, 이미 소개한 조합은 무엇인지, 서로의 조건이 충돌하지 않는지를 사람이 늘수록 감당할 수 없었다. 그걸 정리할 겸 도구로 만들었다.

## 구조

- 모바일 웹 프런트엔드(Next.js)와 단일 파일 FastAPI 백엔드로 나뉜다. 관리자 운영 도구가 같은 프런트엔드에 있다.
- 사용자는 다단계 폼으로 프로필과 원하는·기피하는 조건을 등록한다. 사진은 브라우저가 presigned URL로 Cloudflare R2에 직접 올린다.
- 관리자는 Gemini로 후보를 채점해(1:N 추천, N:M 배치 추천) 매칭을 만든다. 같은 추천인끼리, 이미 매칭된 조합, 진행 중·정지 사용자는 후보에서 자동으로 빠진다.
- 매칭이 만들어지면 24시간 만료되는 공유 링크로 상대 프로필을 보여 준다. 양측이 모두 수락해야 연락처를 교환한다.
- 제안을 거절하면 1점, 24시간 안에 응답하지 않으면 1.5점을 받는다. 누적 3점 이상이면 14일 동안 매칭에서 빠지고, 점수는 매달 초기화된다.
- 제안 링크와 연락처는 운영자가 카카오톡으로 직접 보냈다. 카카오 메시지 API는 사업자등록이 필요해 쓰지 않았다.
- Cloud Scheduler가 하루 한 번 자동 매칭 엔드포인트를 호출한다.

## 기술 스택

- 프런트엔드: Next.js 15(App Router), React 19, TypeScript, Tailwind CSS, shadcn/ui, Vercel
- 백엔드: Python, FastAPI, SQLAlchemy, Google Cloud Run
- DB: Neon(서버리스 PostgreSQL), 로컬은 SQLite
- 이미지: Cloudflare R2
- LLM: Gemini(`gemini-2.5-flash` → `gemini-3.6-flash`). AI Studio로 시작했다가 선불 크레딧에서 429가 나서 Vertex AI로 옮겼고, 로컬은 AI Studio 키로 폴백한다.
- 배치: Cloud Scheduler
- 관리자 인증: Google OAuth 후 자체 JWT

## 어려웠던 점

**AI 추천 결과 캐싱.** 같은 후보를 반복 채점하지 않도록 타겟별 최근 이력에 결과를 캐시하고, 새 후보만 Gemini에 보낸 뒤 가장 최근 행을 병합해 덮어썼다. 호출 비용은 줄었지만 타겟당 사실상 1행만 남아, 몇 번 호출했고 캐시가 몇 번 맞았는지를 나중에 복원할 수 없었다.

**공유 링크와 본인 확인.** 링크마다 256비트 토큰을 쓰고, 토큰 불일치(404)·24시간 경과(410)·이미 응답함(403)을 차례로 확인한다. 응답에서는 이름·연락처·자기소개 원문을 스키마 수준에서 뺀다. 화면은 프로필을 그리기 전에 "○○○님에게 전달된 프로필입니다"로 본인 확인을 받는다. 다만 이 확인은 클라이언트 오버레이라, 개인정보를 뺀 페이로드 자체는 브라우저에 도달한다.

**LLM이 UUID를 옮겨 적지 못하는 문제.** 후보의 36자 UUID를 응답에 그대로 복사하지 못해 결과가 통째로 유실되는 일이 있었다. 후보를 `B1`, `B2` 같은 짧은 라벨로 바꿔 요청하고 응답에서 실제 UUID로 되돌렸다.

**스케줄러 중복 실행.** 처음엔 앱 안의 APScheduler로 일일 자동 매칭을 돌렸는데, Cloud Run 인스턴스가 여러 개 뜨면 각자 실행해 한 사용자에게 매칭이 두 개 생겼다. 자동 매칭은 Cloud Scheduler가 내부 엔드포인트를 하루 한 번 호출하도록 밖으로 빼고, 앱 안에는 월 1회 페널티 초기화만 남겼다.

## 운영 결과

2026년 3월부터 8월까지 약 6개월 운영했다. 유효 가입 61명, 생성된 매칭 119쌍 중 양측이 모두 수락한 것은 11쌍(9.2%)이었다. 매칭 성사율이 기대만큼 나오지 않아 운영을 접었고, 종료에 맞춰 실제 사용자 데이터는 모두 파기했다.

실제로 만든 매칭의 AI 적합도 점수는 평균 78.6점이었지만 성사율은 9.2%였다. 점수는 조건 문장이 서로 맞는지만 볼 뿐, 실제 결정 요인은 반영하지 못했다. 6개월 GCP 비용은 16,627원이었고 그중 64%가 LLM 호출이었다. 일일 자동 매칭은 활성 사용자가 있든 없든 매일 Gemini를 호출해, 종료 직전 30일 동안 신규 가입은 약 5건인데 스케줄러는 30회 실행됐다.
